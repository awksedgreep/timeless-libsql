# Wide raw frame result — 2026-07-31

Session 5 adds `timeless_raw_frame` as an additive wide-fanout interface. The
existing row-oriented `timeless_raw` and one-blob-per-series
`timeless_raw_batches` interfaces remain unchanged.

## Public contract

`TRF1` is one little-endian columnar blob:

```text
"TRF1" | series_count:u32 | total_points:u64 |
series_ids:i64[series_count] | point_counts:u32[series_count] |
timestamps:i64[total_points] | value_bits:u64[total_points]
```

Empty series are omitted. Counts partition the two point columns; timestamps
retain stable raw-query order within each series and values retain exact
IEEE-754 bits. Series slice order is unspecified, matching SQL without
`ORDER BY` and TimelessMetrics' existing multi-series contract.

## Direct extension result

Command:

```console
cargo run --release --manifest-path tools/bench/Cargo.toml --bin query-read -- \
  target/release/libtimeless_ext.so --series 12000 --points 60 --runs 10
```

Dataset: 12,000 series x 60 points = 720,000 persisted points.

| Path | Median | p95 | Result |
|---|---:|---:|---:|
| `timeless_raw_batches` | 74.416 ms | 79.948 ms | 12,000 rows |
| `timeless_raw_frame` | 63.636 ms | 66.973 ms | 1 row |

The frame avoids 11,999 SQLite row crossings and repeated label/blob
allocations while retaining the ordinary batch TVF for SQL consumers.

## TimelessMetrics result

The paired public benchmark measured 113.142ms median / 113.881ms p95 for the
eager 12K-series result, down from 344.221ms at the start of Session 5 (3.04x)
and 372.787ms in the original baseline (3.29x). The exact and narrow medians
improved from 0.348/3.632ms to 0.283/1.978ms, so the selective path did not
regress.

Attribution on the final run:

| Stage | Median | p95 |
|---|---:|---:|
| One-row frame fetch | 77.696 ms | 82.906 ms |
| Cached-label lookup | 4.346 ms | 5.116 ms |
| Direct final-map decode | 12.722 ms | 44.490 ms |
| Fetch + labels + final decode | 112.360 ms | 116.105 ms |
| Public `query_multi` | 113.142 ms | 113.881 ms |

The eager result's external-term size is 12,959,022 bytes. A fresh worker
sampled at 1ms intervals peaked 120,596,408 bytes above baseline (9.306x), and
the benchmark now fails if this exceeds 10x. The 11,664,016-byte frame and the
final BEAM result dominate that intentional bound.

## Correctness and compatibility

- Core buffered/persisted batch results match single-series queries exactly.
- Extension unit tests pin version, layout, omission, timestamp order, and
  non-finite value bits with checked count/size arithmetic.
- The native decoder rejects truncated, malformed, count-inconsistent, and
  unknown-version frames and preserves series/point order.
- CLI section 34 covers the frame header, omission, and fresh-process reopen.
- No on-disk, shadow-table, transaction, or replication-visible format changed.
